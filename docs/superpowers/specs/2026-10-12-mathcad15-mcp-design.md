# Mathcad 15 MCP — дизайн

Дата: 2026-10-12. Статус: утверждён пользователем по разделам в чате; спек фиксирует итог.

## Цель

Стандартный stdio MCP-сервер, который даёт агенту (Claude Code и локальная Qwen в LM Studio)
полную работу с листами Mathcad 15 (.xmcd):

- генерировать новые листы: текст, формулы с единицами, функции, матрицы, Given/Find,
  программы, интегралы/суммы/производные, символьные вычисления, графики X-Y;
- работать с готовыми: открыть, прочитать (формулы + результаты + ошибки), поменять
  исходные данные, пересчитать, прочитать результаты, найти ошибки, экспортировать.

Готовых MCP для Mathcad 15 нет (существующие — для Prime). Старая запись `mathcad`
в `~/.claude.json` (клон для Prime) сломана и заменяется.

## Ограничения

- Mathcad 15 (14.1.1.488, 32-bit COM LocalServer `Mathcad.Application`).
- Пользовательский Mathcad не трогаем: сервер создаёт **свой** скрытый экземпляр
  (`DispatchEx`), закрывает только его (`Quit(2)`), при зависании убивает только свой PID.
- Никаких нажатий клавиш и кражи фокуса (пользователь может играть).
- Схемы инструментов короткие: локальная модель с маленьким контекстом. 6 инструментов.
- Ответы — компактный текст, не JSON.

## Архитектура

Пакет `src/mathcad15_mcp/`:

| Модуль | Ответственность |
|---|---|
| `expr.py` | AST выражений + парсер выражений DSL (Pratt) |
| `dsl.py` | Разбор листа DSL: строки/блоки → список регионов (AST) |
| `mathml.py` | AST ↔ XML math30 (компиляция и декомпиляция) |
| `plot.py` | Двоичный блоб графика: дерево осей ↔ AST |
| `units.py` | Текст результата из `<result>` (числа, единицы, матрицы, комплексные) |
| `worksheet.py` | Файл .xmcd: регионы, вставка/замена, раскладка, binaryContent |
| `engine.py` | COM Mathcad в отдельном STA-потоке, таймауты, перезапуск |
| `render.py` | Компактный текстовый вывод листа для агента |
| `server.py` | MCPServer, 6 инструментов, instructions |
| `help.py` | Справка по DSL (`mc_help`) |

Поток `mc_write`: DSL → `dsl.parse` → регионы → `worksheet.build` (оценочная раскладка)
→ engine: open, recalc, SaveAs во временный xmcd → прочитать реальные размеры →
переложить → engine: open, recalc, SaveAs в целевой файл (родной файл Mathcad с
рендерингами) → `render` (формулы + результаты + ошибки).

## Инструменты

Нумерация регионов `[n]` — 1-based, в порядке сверху вниз (затем слева направо).

| Инструмент | Аргументы | Делает |
|---|---|---|
| `mc_read` | `path`, `regions?` ("3-8"), `errors_only?` | Открыть, пересчитать, показать регионы как DSL + результаты + ошибки |
| `mc_write` | `path`, `text`, `overwrite?` | Новый лист из DSL; ответ как у `mc_read` |
| `mc_edit` | `path`, `start`, `end`, `text` | Заменить регионы `start..end` (вкл.) регионами из `text`. `end = start-1` — вставка перед `start`; пустой `text` — удаление. Остальные регионы переносятся как XML без перегенерации, ниже лежащие сдвигаются |
| `mc_calc` | `path`, `set?` {имя: "выражение DSL"}, `get?` [имена], `save?` | Подставить исходные данные (замена правой части первого определения имени), пересчитать, вернуть значения `get` с единицами и все ошибки. Без `save` файл не меняется |
| `mc_export` | `path`, `out`, `format?` (pdf/rtf/html/xmcd — по расширению `out`) | Экспорт через Mathcad SaveAs |
| `mc_help` | `topic?` | Справка по DSL: syntax, units, program, solve, plot, symbolic, examples |

Пример ответа:

```
beam.xmcd — 7 регионов, 1 ошибка
[1] # Расчёт балки
[2] L := 6 m
[3] q := 12 kN/m
[4] M := q*L^2/8
[5] M = ? kN*m  → 54 kN·m
[6] σ := M/Wx  ✗ Wx: переменная не определена
[7] plot: x=t, y=sin(t)
```

## DSL

Одна инструкция — один регион. Пустые строки и `// комментарий` игнорируются.

| Конструкция | DSL | XML |
|---|---|---|
| Заголовки/текст | `# H1`, `## H2`, `### H3`, `text: абзац` | `<text><p style=…>` |
| Определение | `x := 2.5 m`, `f(x, y) := x*y` | `ml:define` (+ `ml:function`) |
| Глобальное | `g :== 9.81 m/s^2` | `ml:globalDefine` |
| Вычисление | `M = ?`, `M = ? kN*m` | `ml:eval` (+ `ml:unitOverride`) |
| Символьно | `e -> ?`, `e | factor -> ?`, `e | solve, x | float, 5 -> ?` | `ml:symEval` + `ml:command` |
| Индексы | `v[i]`, `A[i, j]`, столбец `A^<j>`, литеральный `M.max` | `indexer`, `matcol`, `id subscript` |
| Операторы | `+ - * / ^`, унарный `-`, `!`, `'` (транспонирование), `< > <= >= != ==`, `and or` | `plus … pow, neg, factorial, transpose, lessThan…, equal, and, or` |
| Единицы | `6 m`, `12 kN/m` — число и идущее за ним имя перемножаются | `mult` |
| Числа | `1.5e-3`, `3i`, `"строка"` | `real`, `imag`, `str` |
| Диапазон | `i := 0..N-1`, `t := 0, 0.1..10` | `ml:range` (+ `sequence` для шага) |
| Матрицы | `[1, 2; 3, 4]` | `ml:matrix` (по столбцам) |
| Анализ | `integral(e, x, a, b)`, `deriv(e, x)`, `deriv(e, x, n)`, `sum(e, i, a, b)`, `sum(e, i)`, `prod(...)`, `limit(e, x, a)`, `limit(e, x, a, "+")` | lambda-операторы |
| Операторы-функции | `sqrt(x)`, `nthroot(x, n)`, `abs(x)`, `det(A)`, `vsum(v)`, `vectorize(e)` | `sqrt, nthRoot, absval, determinant, vectorSum, vectorize` |
| Решатели | `Find(x, y)`, `Minerr`, `Maximize(f, x)`, `Minimize`, `polyroots(c)`, `Odesolve(t, b)`, `genfit(...)` | элементы `ml:Find` и т. п. |
| Given | `Given` + строки с отступом: `x^2 + y^2 = 6` (здесь `=` — ограничение) | регион `Given` + регионы `ml:equal` |
| Программа | `f(n) :=` + тело с отступом: `s <- 0`, `for i in 1..n:`, `while c:`, `if c:` / `else:`, `return e`, `break`, `continue`, `try:` / `on error:`; последняя строка — значение | `ml:program`, `localDefine`, `for`, `while`, `ifThen`, `otherwise`, `return`, `break`, `continue`, `tryCatch` |
| График | `plot: x=t, y=sin(t), cos(t), t=0..10, xlim=0..10, ylim=-1..1` | `<plot>` + двоичный блоб |
| Сырой XML | `raw: <ml:…>` или `raw: <region …>…</region>` | как есть |

Правила графика: ключи `x`, `y` — списки трасс через запятую (до 16), `xlim`/`ylim` —
фиксированные пределы, без них автомасштаб. `t=a..b` (имя не `x/y/xlim/ylim`) создаёт
перед графиком регион `t := a, a+(b-a)/200..b` (или с явным шагом `t=a, s..b`).
Если трасс X меньше, чем Y, одна X идёт на все Y (как в Mathcad).

Декомпиляция (XML → DSL) покрывает тот же набор; неподдерживаемое показывается как
`raw: …` (усечённо в `mc_read`), поэтому чтение никогда не падает.

## Раскладка

Единицы xmcd — пункты (страница 612×792, поля 86.4). Один столбец: `left = 18`,
регионы сверху вниз с зазором 9 pt. Mathcad сам пересчитывает `width/height` и
держит базовую линию `align-y`, поэтому проход двухфазный: оценка → Mathcad SaveAs
во временный файл → реальные высоты и `align-y − top` → финальная раскладка.
`mc_edit`: новые регионы встают на место заменённых, нижние сдвигаются на разницу высот.

## Двоичный формат графика (реверс)

`<plot item-idref=K>` → `<binaryContent><item item-id=K content-encoding="gzip">` с
gzip-блобом. Внутри: объявления классов (eqRegion, docRegion, shpBox, shpRect с
размерами), затем `04 'tree' ver …` (22 байта заголовка; Mathcad 15 пишет ver 0x1b,
cls 0x32, строки UTF-16LE), дерево, хвост `[next_id] 00 02 00 00 00`, затем
`d2_graph_format`, `graphData`, `axisFormat`, `trace2D` (16 стилей трасс по умолчанию).

Запись узла: `id cls type(2) 00 00 rel parent` (байт ≥ 0x40 экранируется префиксом 0x40).
`rel`: 0x40 левый / 0x80 правый потомок; младшие биты листа: 0x24 имя, 0x34 число,
0x36 число-автопредел. Лист `020f`: `00 00 [len+1] [01 для числа] len chars 00`;
пустой `000f`: `00 00 00`. Узлы `954b` (neg) и `8e70` (скобки) имеют байт `00` после
заголовка. После поддерева каждого нелистового узла (кроме корня) — закрывающий байт
(`01` для `06ca` mult, иначе `00`). Типы: `19c1` корень, `9fc1` пара, `0ac3` запятая,
`89c7` +, `88c7` −, `06ca` ×, `07fb` ÷, `05cc` степень, `04fd` индекс, `34fd` столбец,
`12ce` вызов (имя, `8e70`(аргументы через `0ac3`)), `954b` минус.
Дерево: `root(pair(Yaxis, Y2axis), Xaxis)`, ось = `pair(pair(pair(hi, lo), pair(m1, m2)), expr)`.
Проверено: сериализатор совпадает побайтово с 631 из 633 разобранных деревьев корпуса;
сгенерированные графики (две трассы `sin(t)`, `0.5·cos(2t)`; `X[i]^2` от `X[i]`)
корректно строятся Mathcad 15.

## Движок (COM)

- Отдельный поток с `CoInitialize`, очередь задач; все вызовы COM только из него.
- Экземпляр создаётся лениво, `SetOption(0, False)` (без message box), `Visible = False`.
  PID определяется по разнице списков `mathcad.exe` до/после запуска.
- Таймаут операции (по умолчанию 120 с, `MATHCAD_TIMEOUT`): убиваем только свой PID,
  экземпляр пересоздаётся при следующем вызове; ответ — ошибка с пояснением.
- При ошибке COM (RPC unavailable) — один перезапуск и повтор.
- На выходе сервера (`atexit`, закрытие stdin) — `Quit(2)`.
- Ошибки регионов: `MathInterface.HasError/ErrorMsg`; сырые коды вида
  `bad_variable\t…` переводятся в текст (таблица в `render.py`).

## Обработка ошибок

- Ошибка синтаксиса DSL → ответ инструмента с номером строки, текстом строки и
  ожидаемой конструкцией; файл не пишется.
- `mc_write` без `overwrite` на существующий файл → отказ.
- Файл не .xmcd (например .mcd) → `mc_read`/`mc_calc`/`mc_export` работают через COM
  (Mathcad откроет), `mc_edit` требует .xmcd (предлагает `mc_export` в .xmcd).
- Mathcad недоступен → `mc_read` по XML без пересчёта (результаты из файла) с пометкой.

## Тестирование

- Юнит: парсер выражений и DSL, компиляция в XML, декомпиляция, рендер результатов.
- Корпус (≈3.9k регионов math из Handbook): XML → DSL → XML, нормализованное сравнение;
  цель ≥ 95% без `raw:`, 100% без падений.
- Графики: round-trip деревьев корпуса; генерация → Mathcad → PNG рендеринга не пустой.
- Интеграция (маркер `mathcad`): mc_write → результаты/ошибки; mc_edit; mc_calc set/get;
  mc_export pdf; MCP по stdio: initialize + tools/list + tools/call.

## Регистрация

- `~/.claude.json` → `mcpServers.mathcad` = stdio `…\mathcad15-mcp\.venv\Scripts\python.exe -m mathcad15_mcp`
  (бэкап перед правкой).
- LM Studio `~/.lmstudio/mcp.json` → `mathcad` с той же командой.
